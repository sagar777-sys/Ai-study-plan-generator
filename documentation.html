The Study Almanac

A web application that generates personalized AI study plans using fuzzy-logic reasoning and large language models — wrapped in a vintage archival interface.

STACK: REACT 19 · VITE · TYPESCRIPT · TAILWIND CSS 4 · CONVEX (DB + AUTH + ACTIONS) · BUN  ·  SEPTEMBER 2026 Vintage edition

01Overview

The Study Almanac lets a user sign up with an email, fill a short study brief (subject, exam date, hours per week, prior knowledge), watch a live fuzzy-inference preview as they type, and compose a week-by-week study plan that is filed under their own account.

Two engines cooperate: a 13-rule Mamdani fuzzy-logic system decides intensity, review cadence and sitting length from the brief, and a large language model writes the actual week-by-week sessions from that verdict. If the model is unavailable or its answer cannot be parsed, a deterministic composer produces a complete plan from the same fuzzy verdict — the app never fails open.

02Features

Email sign-in only

Six-digit email OTP via Convex Auth. One method, exactly as specified for version 1.

Live fuzzy inference

Fuzzification chips, three defuzzified gauges, sitting estimate, and a full rule trace with membership strengths (μ) — recomputed on every slider move.

AI plan composition

A Convex node action sends the brief plus the fuzzy verdict to an LLM, which writes titles, focus lines, sessions (day/minutes/kind) and checkpoints.

Guaranteed fallback

If no AI key exists or the model misbehaves, the deterministic Almanac engine composes the plan from the same verdict. No placeholder states.

Filed archive

Every plan is saved with ownership checks; reopen or withdraw past folios at any time.

Print-friendly folios

Chrome is excluded from print; a plan prints cleanly as a study document.

04The fuzzy-logic engine

Inputs are fuzzified with triangular/trapezoidal membership functions, fired through 13 hand-written linguistic rules using min-implication, aggregated with max, and defuzzified by centroid over 0–100 universes.

InputLinguistic terms
Hours per week (1–60)scarce · moderate · ample
Days until exam (1–365)urgent · near · distant
Prior knowledge (0–10)weak · working · strong
Output (0–100)Linguistic terms
Intensitygentle · steady · rigorous
Review cadencerare · weekly · dense
Session lengthshort · medium · long → crisp minutes (20–90)

Example rule: IF hours = moderate AND exam = near AND knowledge = working THEN intensity = steady, cadence = weekly, session = medium. The exact same infer() function runs in the browser for the live preview and in Convex for the authoritative plan, so the preview always matches what is filed.

05AI composition

  • The compose action builds a strict JSON prompt: week count, session count, minutes, and the fuzzy verdict.
  • The model's response is structurally sanitised: exact week count, sessions per week bounds, minutes clamped 10–180, session kinds whitelisted to study | practice | review | mock, string length caps.
  • Any failure (no key, timeout, unparseable JSON) falls back to the deterministic engine; the folio is stamped LLM or Almanac engine accordingly.
  • Keys are read server-side only, inside the "use node" action via process.env — never shipped to the client.

06Data model

plans
  userId        Id<"users">            (indexed: by_user)
  inputs        { subject, examDate, hoursPerWeek, priorKnowledge, daysUntilExam, notes? }
  fuzzy         { intensity, cadence, session, sessionMinutes, labels{...}, trace[] }
  weeks[]       { index, title, focus, sessions[{ day, task, minutes, kind }], milestone }
  composedBy    "llm" | "almanac"
  createdAt     number

Queries and mutations enforce ownership: a user can only list, open, or delete their own plans.

07Local setup

Requirements: Bun, a Convex account (the template ships configured).

bun install          # install dependencies
bun convex dev       # start Convex + codegen, then in another terminal:
bun run dev          # start the Vite dev server

Routes: / landing page · /auth sign-in · /dashboard protected workspace.

09Deployment

  1. Backend: bun convex deploy pushes functions/schema; set optional OPENAI_* vars in the deployment environment if desired.
  2. Frontend: bun run build outputs dist/ — host on any static provider (Render, Netlify, Vercel, GitHub Pages) with VITE_CONVEX_URL pointing at the deployed Convex deployment. SPA rewrite of all routes to /index.html required.
  3. Live demo: the hosted Freebuff preview of this project is the live demo — sign in at /auth and compose a plan at /dashboard immediately.
